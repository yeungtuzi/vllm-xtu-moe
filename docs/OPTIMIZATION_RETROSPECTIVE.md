# 复盘:AI 的性能优化为什么"局部且盲目",以及人类架构师的方向性指导如何破局

> 本文由 2026-09 的 `vllm-xiaotu-moe` 会话沉淀,**全部结论都对应仓库里可查的证据**
> (`report/tuning/NOTES.md`、`TRIED_AND_REVERTED.md`)。目的不是评价某次协作,而是把
> "哪种指导最省时间"写成可复用的清单。

## 一、核心结论

**AI 的性能优化天然是"局部 + 盲目"的:**
- **局部**:它只会优化**它能测量、能改动**的那一层。本会话里就是 CPU 解码内核的内层循环
  —— 于是它在那里连续做了 ~30 轮实验(§66-§95)。
- **盲目**:它缺少**系统级的先验**——"draft 应该在哪块硬件上"、"生产环境的接受率应该是多少"、
  "C=2 应该扩展"。没有这些先验,它会**把可测的邻域穷举到尽头**,每一步在局部都"正确",
  但整个搜索空间是错的 —— 于是长时间迭代/回退后卡死。
- **人类架构师不可替代**:他的一句话(往往来自生产环境的观察)就能**换掉整个搜索空间**。
  下面的案例里,每一条人类指导的"成本"是一句话,收益是**数轮到数十轮**。

## 二、具体案例(本会话,按"AI 卡死的形态 → 人类的一句话 → 破局结果"组织)

### 案例 1:AI 在 CPU 内核里穷举 30 轮,人类一句"先结案、转第二条"
- **卡死形态**:§113-§142 期间,AI 把解码内核的"每线程 1.9 vs lk 2.2 GB/s"当靶子,
  连续尝试:奇偶 seqlock 去锁、cacheline padding、静态/批量领票、K-major 布局、
  bf16 点积(dotp16 加 NR 列分块)、列分块参数、GCHUNK/SHARDSPLIT/NSHARD/线程数/spin/master 绑核…
  **绝大多数中性或回退**(清单见 `TRIED_AND_REVERTED.md` R1-R85)。
  它甚至三次自我推翻(§135 提出 K-major → §136 自我否掉 → §140 又回到 op-bound → §141 再否掉)。
- **人类指导(第 96 轮)**:"第一条视为已经完成,把还能做的工作写到后续规划之后以后我们再回顾,
  现在优先级低。"
- **结果**:AI 立即产出 `FUTURE_PLAN.md` 并把重心转向第二条;之后**几轮内就拿到了第二条的
  全部关键事实**(C=1/C=2 口径、预填充分段计时、显存精确账、配置矩阵)。
  ⇒ **"划界"是最便宜、收益最大的指导。**

### 案例 2:AI 有了公式却没有做那个显然的实验,人类一句"C=2 几乎不涨?"点破
- **卡死形态**:§148/§152 AI 已经推出"每输出 token 要搬 13.3 GB 权重 ⇒ 17 t/s 上限"的公式,
  并列出"接受率是第一杠杆",但**没有先去测"关掉投机"这一最便宜的对照**。
- **人类指导(第 101 轮)**:"目前 c=2 的时候吞吐只有很少提升,那么问题之一是没有充分并行化?"
- **结果**:AI 补做无投机对照 ⇒ **C=1 22.2 t/s、C=2 聚合 40.4 t/s(+82%)**,而有投机 k=5 时
  C=2 只 +6% ⇒ **证实"投机在净亏"**;顺带发现 `qlen=1→2` 每层只涨 19%(**两 token 共享专家**)。
  ⇒ **人类的一个"预期形状"(C=2 应该涨)就是最强的判据。**

### 案例 3:AI 把"接受率低"归因于采样参数,人类给出生产基线一句话定标
- **卡死形态**:AI 观察到接受率 ≈1.3/步(≈26%/位),推测是 `draft_sample_method: probabilistic`,
  准备去扫 k=3/5/7 与采样网格 —— 方向不算错,但**没有量级感**。
- **人类指导(第 102 轮)**:"生产环境:生成 35 tok/s、draft 90 tok/s、**接受率 40-50%**、
  **平均接受 3 个 token**。"
- **结果**:立刻有了标尺 —— 我们的接受率只有生产的 ~60%,而**生产是净赚、我们是净亏**;
  再叠加"每步 74 ms ÷ 接受 3 ⇒ 5.8 GB/token ⇒ ~39 t/s"的算术,目标第一次变得可达。
  ⇒ **给出"参考数字"比给出"方向"更省时间。**

### 案例 4:【最关键】人类一句"投机模型应该跑在 GPU 上吧"直接命中根因
- **卡死形态**:AI 在 §152 已经算出"投机净亏"并归因到接受率,继续沿着采样参数往下走。
  **它从未去查 draft 到底跑在哪块硬件上。**
- **人类指导(第 102 轮末)**:"投机模型应该运行在 gpu 上面吧。"
- **结果**:AI 核对后证实:**模型是 43 层 + `num_nextn_predict_layers=1`(1 层 MTP 作 draft)**,
  而插件 `hybrid_model.py:501-511` **默认把 draft 副本排除在 GPU 常驻之外**(注释里写的理由是
  "常驻会把显存占用翻倍 ⇒ 常驻层数上不去")⇒ **draft 的 MoE 专家跑在 CPU 引擎上**,
  每个投机步额外走一遍 CPU 权重搬运 ⇒ 这正是"k=5 让每步 74→ 而无投机只要 43 ms"、
  "有投机时 C=2 只 +6%"的直接原因。**这是 30+ 轮微优化从未触及的一层。**
  ⇒ **架构层面的"这个东西该放在哪"是人类先验,AI 从数据里推不出来。**

### 案例 5:人类用"数量级"逮住 AI 的一次未标注外推
- **卡死形态**:AI 同时写下 "234 GB/s(引擎实测)" 与 "192 核 × 2.2 = 422 GB/s 仍够不到峰值",
  把**实测值**与**自己外推的值**混在一段话里。
- **人类指导(第 102 轮)**:"但是你又说 234 GB/s(正好是引擎实测带宽)"。
- **结果**:AI 更正为三档口径(实测 234 / 外推 422 / 机器峰值 783),并承认 422 **从未实测**;
  进一步用同形探针证明"每次 64B 一次依赖载入"的朴素循环每线程也只有 ~2.5 GB/s,
  ⇒ 引擎的每线程速率是**正常 MLP 水平**,不是解码异常。
  ⇒ **人类对"数字性质"的敏感度,能阻止 AI 用外推值当结论。**

### 案例 6:人类的硬约束反过来被 AI 的实测验证
- **人类长期约束**:"每 CCD 4-5 核"、"权重按 NUMA node 分片、每 node 只读写本地内存、
  跨 node 只交换小数据"、"删掉 singlecopy、永远不许用"。
- **AI 的实测**:`THREADS=120` 优于 192(§125)、`NSHARD=8` 已是最优而 16 直接崩(§125)、
  跨 rank 归约走共享内存(§155)…
  ⇒ 这些**不是 AI 探索出来的,是被人类约束"框"出来的**;约束本身省掉了大量错误区域。

## 三、可复用的指导清单(给"人给 AI 派活"时的最小成本清单)

按"一句话成本 / 收益"排序:

1. **划界**:哪些算达标、哪些结案、哪些降优先级。*(案例 1)*
2. **参考数字**:对标机器的**实测**值(吞吐、接受率、延迟、每层耗时、显存占用)。*(案例 3)*
3. **预期形状**:什么东西应该随什么变化(例如"C=2 应该涨"、"接受率应该 40-50%")。*(案例 2)*
4. **架构放置**:每一块(权重/草稿/缓存)应该在**哪块硬件/哪级存储**上。*(案例 4)*
5. **不变量/硬约束**:拓扑、绑核、分片、禁止项。*(案例 6)*
6. **口径定义**:指标是单流还是聚合、峰值还是实测、含不含 TTFT。*(案例 5)*

## 四、给 AI 侧的自我约束(本会话血的教训)

- **测前先清场**:同一个基线数字必须在干净状态重采(§147 曾把"反复起停的残差"误当回归)。
- **一次只改一个变量**;每个结论都要能追到"哪一次实测"。
- **区分实测/外推/理论峰值**,并在文中标注(§154)。
- **跨口径不可相减**(§134 曾用我们的 na=32 去比 lk 的 na=12,得出错误的"已反超")。
- **先做最便宜的对照**(关掉某特性再测)再谈调参(案例 2)。
- **凡改动同步结构/内层循环,必须先过数值门禁**(`scripts/check_engine_aligned.sh`,R55)。
- **操作类陷阱**(`pkill -f` 自杀、kill 后不等显存释放)已在 `TRIED_AND_REVERTED.md` 记为 M8/M9,
  本会话仍各复发一次 —— 说明"记录"不等于"免疫",需要工具化(按 PID 杀、等待+校验)。
